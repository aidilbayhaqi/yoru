# Incident Response

1. Detect and create a security event with severity and evidence.
2. Contain: revoke sessions/keys, stop affected integrations, or isolate the service.
3. Preserve logs and evidence. Do not edit financial or audit history.
4. Assess affected users, partners, payments, bookings, and personal data.
5. Eradicate the cause and deploy a reviewed forward fix.
6. Recover gradually and monitor for recurrence.
7. Resolve the security event with a written resolution note.
8. Complete a post-incident review and track corrective actions.

Critical open events intentionally fail the production launch gate.
